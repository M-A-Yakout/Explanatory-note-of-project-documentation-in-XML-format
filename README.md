# ПЗ Генератор

## Запуск без Docker (SQLite)
```powershell
cd backend
python -m venv .venv ; .venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
alembic upgrade head          # создаёт таблицы
python -m app.seed            # супер-админ admin@inpad.ru / ChangeMe2026 + схемы XSD
uvicorn app.main:app --reload
```
```powershell
cd frontend
npm install
npm run dev                   # http://localhost:5173
```
API: http://localhost:8000/docs · Frontend без бэкенда: `VITE_USE_MOCK=true npm run dev`

## Запуск с Docker (PostgreSQL)
`docker compose up --build` — миграции и seed выполняются автоматически.

## Часть 2: что работает
- Регистрация (создать организацию → org_admin, или вступить → designer), вход, JWT (8 ч)
- Восстановление пароля и подтверждение почты: письма печатаются в консоли бэкенда (`EMAIL to=...`)
- Защита страниц по роли; `/admin/*` только для super_admin / org_admin
- Тесты: `cd backend && pytest` (112 тестов)

## Часть 3: объекты (проекты)
- API `/api/projects`: список (поиск, фильтры, сортировка, пагинация), создание, правка, удаление
- Изоляция организаций: чужой объект возвращает 404; эксперт только читает; удаляют только админы
- Страницы: список, форма создания/правки, карточка объекта (`pages/projects/`)
- После обновления: `cd backend && alembic upgrade head` (миграция 0002)

## Часть 4: документы (пояснительные записки)
- API `/api/documents`: список (поиск, фильтры), создание из объекта, автосохранение (`PUT /{id}/data` с `baseRevision`; при расхождении — 409 `conflict`), версии, сравнение (`/diff`), восстановление
- Данные формы: объект, ТЭП, состав документации (12 разделов ПП № 87), нормативные ссылки, примечания; прогресс считается на сервере
- Страницы: список, мастер создания, редактор (5 разделов), история версий со сравнением
- Объект с документами удалить нельзя (409 `has_documents`)
- После обновления: `cd backend && alembic upgrade head` (миграция 0003)

## Часть 5: XML-схемы (реестр XSD)
- API `/api/schemas`: список активных схем (всем), реестр целиком, загрузка, отключение/активация, схема по умолчанию, удаление, структура и скачивание XSD (только super_admin)
- При загрузке XSD компилируется (lxml); `xs:include/import`, `DOCTYPE` и `ENTITY` запрещены (защита от XXE и внешних загрузок); лимит 2 МБ
- Всегда ровно одна схема по умолчанию; схему по умолчанию или с документами удалить нельзя; отключённая схема недоступна для новых документов
- В поставку входят упрощённые рабочие схемы 01.05 и 01.04 (`backend/app/xsd_bundled/`) — это **не** официальные XSD Минстроя; загрузите настоящие через страницу «XML-схемы»
- После обновления: `alembic upgrade head` (миграция 0004) и `python -m app.seed` (загружает схемы)

## Часть 6: генерация XML и проверка
- `POST /documents/{id}/validate` — два уровня: бизнес-правила (BR-*: обязательные поля, формат кадастрового номера, ТЭП, площадь застройки ≤ площади участка, состав, нормативные ссылки, устаревшие редакции СП) и проверка итогового XML по XSD выбранной версии (XSD-*)
- Каждая ошибка привязана к полю формы (`object.developer`, `tei[<id>].value`…); XSD-ошибки сопоставляются с полем через XPath; дубли XSD по тому же полю скрываются
- `GET /documents/{id}/xml` — предпросмотр; `/xml/download` — выгрузка (**всегда перепроверяет** данные, при ошибках 409); `/validation/report` — текстовый отчёт
- Генератор учитывает схему: в блок Object попадают только элементы, объявленные в выбранной XSD; число «8 412,0» → `8412.0`; управляющие символы удаляются, спецсимволы экранируются
- Правка после проверки помечает результат устаревшим и сбрасывает статус «Проверен»
- Страницы: проверка (группы по важности, переход к полю), просмотр XML (дерево/исходный, поиск, копирование, читаемый вид), выгрузка
- После обновления: `alembic upgrade head` (миграция 0005)

## Часть 7: импорт XML
- `POST /documents/import/preview` — анализ файла **без записи в БД**; `POST /documents/import` — создание документа (сервер заново разбирает файл, данные от клиента не принимаются)
- Файл передаётся как base64, поэтому учитывается объявленная кодировка (windows-1251, UTF-8); XML с пространством имён принимается
- Защита: без DTD/ENTITY/сети (XXE, entity-bomb), лимит размера (`MAX_XML_MB`, 20 МБ), лимиты длины полей и числа строк
- Отчёт: что перенесено, что **не перенесено** (с XPath и причиной), что обрезано, замечания XSD к исходному файлу (импорт при этом продолжается), замена схемы, если версия из файла недоступна
- Новый документ получает версию 1 с комментарием «Импорт из <файл>», статус «Черновик»; дальше обычная проверка
- Страница `/app/documents/import`; также доступна из мастера создания и из списка документов

## Часть 8: архив, поиск, массовые операции
- Архив: `POST /documents/{id}/archive` и `/restore` (запоминают, кем и когда; при восстановлении возвращается прежний статус, а «Проверен» — только если проверка не устарела); архивный документ только для чтения; удалить навсегда можно **только из архива** и только администратору
- Массовые операции `POST /documents/bulk` (архив / восстановление / удаление): каждый id обрабатывается отдельно, чужие документы выглядят как несуществующие; `POST /documents/bulk/xml` — ZIP с XML тех документов, что прошли проверку (остальные перечислены в `_skipped.txt`)
- Поиск: фильтры по автору и датам (`authorId`, `updatedFrom`, `updatedTo`), поиск по названию, объекту, адресу, кадастровому номеру; верхняя строка поиска (`GET /search`, Ctrl K, стрелки, Enter)
- Страницы: «Архив», обновлённый список документов (множественный выбор), кнопка «В архив» в редакторе
- После обновления: `alembic upgrade head` (миграция 0006; пересчитывает поисковый текст существующих документов)

## Часть 9: администрирование, аудит, уведомления
- **Журнал аудита** (`/api/audit`, CSV-экспорт): вход и неудачные входы (с IP), регистрация, смена пароля, действия с пользователями и организациями, схемы XSD, объекты, документы (создание, импорт, проверка, выгрузка, архив, удаление), настройки. Имя пользователя сохраняется на момент события. Администратор организации видит только свою организацию. CSV: UTF-8 с BOM, разделитель «;», значения с `= + - @` экранируются (защита от формул Excel)
- **Пользователи и приглашения**: список, поиск, роли, блокировка (действующие сессии прекращаются сразу), сброс пароля, приглашения по почте на 7 дней. Ссылка привязана к конкретному приглашению (nonce): отозванная или заменённая ссылка не оживает, даже если id строки переиспользован. Нельзя менять свою роль/блокировать себя; нельзя снять роль или заблокировать последнего администратора организации
- **Организации** (super_admin): создание, лимиты пользователей и объектов (применяются при регистрации, приглашении, создании объекта; ниже текущего использования снизить нельзя), отключение — все пользователи теряют доступ сразу
- **Профиль**: данные, смена пароля (по текущему паролю), настройки уведомлений
- **Уведомления**: проверка и версии документа, архив, принятие приглашения — автору документа, когда действует кто-то другой; учитываются настройки пользователя; значок в шапке
- **Рабочий стол** и **обзор системы**: статистика по организации; устаревшие результаты проверки не учитываются в счётчиках
- **Настройки системы** (super_admin): запрет выгрузки при предупреждениях, правило об устаревших ссылках, лимит размера XML, подтверждение почты, шаблоны писем
- После обновления: `alembic upgrade head` (миграция 0007, пересчитывает поисковый текст пользователей)
- Письма пока печатаются в консоль бэкенда (`EMAIL to=...`): для реальной отправки замените `core/mailer.py`
