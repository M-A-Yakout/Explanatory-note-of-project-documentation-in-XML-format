# Тестирование

## Автотесты бэкенда

```sh
cd backend
pip install -r requirements-dev.txt
python -m pytest -q --cov=app            # SQLite в памяти, ~40 с
```
Итог: **138 тестов, покрытие 98 %.**

### На настоящем PostgreSQL

```sh
alembic upgrade head                     # схема создаётся реальными миграциями
TEST_DATABASE_URL=postgresql+psycopg://user:pass@host/db DATABASE_URL=$TEST_DATABASE_URL python -m pytest -q
```
Между тестами таблицы очищаются (`TRUNCATE`). Результат: те же **138 тестов проходят и на PostgreSQL**.

### Миграции

```sh
alembic check                                                    # модели == миграции
alembic downgrade base && alembic upgrade head                   # полный цикл
alembic downgrade base && alembic upgrade 0006 && alembic upgrade head   # обновление уже развёрнутой базы
```
Эти три проверки вошли в CI (`.github/workflows/ci.yml`) — они нашли две ошибки, не видимые на SQLite (см. ниже).

## Что покрыто тестами

Авторизация и сессии · изоляция организаций · роли · объекты · документы, автосохранение, конфликты, версии · реестр и проверка XSD (включая защиту от XXE) · бизнес-правила и XSD-проверка · выгрузка (повторная проверка на сервере) · импорт XML (windows-1251, пространства имён, вредоносные файлы, лимиты) · архив и массовые операции · поиск · администрирование, приглашения, лимиты · журнал аудита и CSV · уведомления · настройки · ограничение попыток входа · первый запуск (`seed`) · конфигурация production.

## Сквозные проверки в браузере (Chromium, Playwright)

Выполнялись вручную по ходу разработки на каждой части: вход и защита маршрутов, создание/редактирование объектов и документов, автосохранение и конфликт двух окон, проверка и переход к полю, выгрузка и разбор скачанного файла, импорт (включая windows-1251), архив, приглашения, блокировка, лимит попыток, выход со всех устройств.

**Проверка всей production-схемы** (настоящий `entrypoint.sh` на PostgreSQL, 2 worker'а, nginx с конфигами из поставки): маршрутизация и deep link, кэширование, заголовки безопасности (по одному разу), CSP без нарушений в 12 страницах, скрытие `/docs`, невозможность подделать IP через `X-Forwarded-For` (лимит срабатывает между workers), лимиты размера тела (30 МБ → ответ приложения, 45 МБ → 413 от nginx).

## Нагрузка

Стенд: PostgreSQL, 6000 документов (≈4 КБ данных каждый), 18 000 версий, 30 000 записей аудита, 3000 уведомлений. Медианы на запрос (5 замеров): список объектов 6–7 мс · список документов и фильтры 12–15 мс · глобальный поиск 10 мс · карточка документа 8 мс · проверка одного документа 12 мс · предпросмотр XML 7 мс · журнал аудита 11–23 мс · **статистика рабочего стола 59 мс** (читает результаты проверки всех документов организации). Самый первый запрос после запуска заметно медленнее (холодное соединение и кэш): до ~0,3 с для журнала и до ~0,7 с для статистики рабочего стола.

## Что тестами не охвачено

Firefox и Safari · мобильные браузеры (вёрстка адаптивная, но не прогонялась) · сборка Docker-образов · реальная отправка почты · одновременная работа сотен пользователей.

## Ошибки, найденные только при тестировании на PostgreSQL

1. Миграция 0007 заново создавала тип `role`: **ступенчатое обновление существующей PostgreSQL-базы падало** (на пустой базе всё проходило). Исправлено.
2. Откат миграций оставлял в PostgreSQL типы ENUM, и повторное применение падало. Исправлено.
