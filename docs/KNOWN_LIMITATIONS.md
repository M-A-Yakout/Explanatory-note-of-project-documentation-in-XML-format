# Известные ограничения

Расположены по важности для заказчика.

1. **Нет официальных XSD Минстроя.** Работа идёт на упрощённых схемах 01.05 и 01.04. XML не готов к передаче в экспертизу, пока сервис не приведён к официальной структуре (см. `ACCEPTANCE.md`, раздел «Что НЕ выполнено»).
2. **Письма не отправляются.** Только печать в лог (`core/mailer.py`). Приглашения, подтверждение почты и сброс пароля работают, но ссылку нужно брать из лога, пока не подключён SMTP. Переключатель «Письма на почту» в профиле сохраняется, но пока ничего не делает.
3. **Образы Docker не собирались в среде разработки** (см. `DEPLOYMENT.md`).
4. **Проверка только в Chromium.**
5. **HTTPS не входит в поставку** — нужен внешний прокси с TLS.
6. `xs:include` и `xs:import` в загружаемых XSD запрещены (защита). Если официальные схемы разбиты на несколько файлов, понадобится загрузка набора файлов.
7. Один пользователь — одна организация; супер-администратор видит данные только своей организации в разделах объектов и документов (кроме администрирования).
8. Нет многофакторной аутентификации и истории паролей; сессия 8 часов.
9. Резервные копии — скриптом по cron, не встроенные.

## Известные пределы роста

* **Статистика рабочего стола** читает результаты проверки всех документов организации: ≈ 59 мс на 1700 документов, растёт линейно. При десятках тысяч документов в одной организации хранить счётчики ошибок отдельными столбцами.
* **Поиск** — `LIKE '%…%'` по служебному столбцу (полный просмотр таблицы). Для сотен тысяч документов или миллионов записей аудита добавить индекс `pg_trgm`.
* История версий хранит полный снимок данных; при тысячах версий на документ потребуется очистка старых.
