# Развёртывание

> Образы Docker в среде разработки **не собирались** (Docker там недоступен). Проверено другим способом: настоящий `entrypoint.sh` + PostgreSQL + nginx с теми же конфигами + собранная фронтенд-сборка, под нагрузкой реального браузера (см. `TESTING.md`). Первую сборку образов проверьте на тестовом сервере.

## Требования

Сервер с Docker и Docker Compose v2; 2 ГБ ОЗУ, диск под БД. HTTPS вынесите на внешний прокси/балансировщик (nginx из поставки слушает HTTP).

## Первый запуск

```sh
cp .env.example .env
#  POSTGRES_PASSWORD, SECRET_KEY  ->  openssl rand -hex 32   (пароль БД — только URL-безопасные символы, hex подходит)
#  SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD  — первый супер-администратор (пароль не короче 10 символов, не «ChangeMe2026»)
#  PUBLIC_URL — адрес сайта (попадает в ссылки писем), HTTP_PORT — порт nginx
docker compose up -d --build
```

При старте контейнер API сам: ждёт БД → применяет миграции → создаёт администратора (если его ещё нет; существующий не трогается, пароль не сбрасывается) → загружает базовые XSD → запускает сервис. Откройте `PUBLIC_URL`, войдите под `SEED_ADMIN_EMAIL`, **смените пароль** (Профиль) и создайте организации.

Проверка: `docker compose ps` (все `healthy`), `curl http://localhost/api/health` → `{"status":"ok","db":"up"}`.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ENVIRONMENT` | `development` | `production` включает защитные проверки конфигурации и скрывает `/docs` |
| `DATABASE_URL` | локальный PostgreSQL | `postgresql+psycopg://user:pass@host:5432/db` |
| `SECRET_KEY` | — | Ключ подписи токенов; ≥ 32 символов; смена завершит все сессии |
| `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD` | — | Первый супер-администратор |
| `FRONTEND_URL` (`PUBLIC_URL` в compose) | `http://localhost:5173` | База ссылок в письмах |
| `REQUIRE_EMAIL_CONFIRMATION` | `false` | Начальное значение; дальше меняется в «Настройки системы» |
| `ACCESS_TOKEN_MINUTES` | `480` | Срок жизни сессии |
| `RATE_LIMIT_ENABLED` | `true` | В production отключать нельзя |
| `WEB_CONCURRENCY` | `2` | Число процессов API |
| `CORS_ORIGINS` | `["http://localhost:5173"]` | В compose `[]` — UI и API на одном origin |

Максимальный размер XML, правила проверки и шаблоны писем меняются прямо в интерфейсе («Настройки системы») и хранятся в БД.

## Обновление

```sh
scripts/backup.sh                 # всегда сначала резервная копия
git pull && docker compose up -d --build
```
Миграции применяются автоматически при старте. Проверено на PostgreSQL: ступенчатое обновление существующей базы (`0006 → head`), полный откат и повторное применение, совпадение моделей и миграций (`alembic check`).

## Резервное копирование

```sh
scripts/backup.sh                 # backups/pz_ДАТА.dump, хранятся 14 последних
scripts/restore.sh backups/pz_2026-11-17_0300.dump   # ЗАМЕНЯЕТ текущие данные
```
Запускайте `backup.sh` по cron (раз в сутки) и копируйте файлы за пределы сервера. Восстановление из копии на чистом стенде стоит проверить до того, как оно понадобится.

## Почта

Письма (приглашения, подтверждение, сброс пароля) **пока печатаются в журнал контейнера** `api` (`docker compose logs api | grep EMAIL`). Для настоящей отправки замените функцию `send_email` в `backend/app/core/mailer.py` на отправку через SMTP — больше ничего менять не нужно.

## HTTPS

Поставьте перед `web` прокси с TLS и добавьте строку `Strict-Transport-Security` (закомментирована в `frontend/nginx/security-headers.conf`). Порт API (8000) наружу не публиковать: доверие к `X-Forwarded-For` держится на том, что запросы приходят только от nginx.

## Эксплуатация

* Логи: `docker compose logs -f api web`.
* Здоровье: `/api/health` (проверяет БД), `/healthz` (nginx).
* Масштабирование: счётчики попыток входа лежат в БД, поэтому можно увеличивать `WEB_CONCURRENCY` и запускать несколько экземпляров API за одним nginx.
* Размеры: при ~6000 документов и 30 000 записях аудита медианы основных запросов составляли 6–60 мс (PostgreSQL), первый запрос после запуска — до ~0,7 с. Известные места роста — в `KNOWN_LIMITATIONS.md`.

## Неполадки

| Симптом | Причина |
|---|---|
| API не стартует: «Небезопасная конфигурация production» | Слабый/стандартный `SECRET_KEY` или `SEED_ADMIN_PASSWORD` |
| «database is unreachable» | БД не поднялась / неверный `DATABASE_URL` (спецсимволы в пароле) |
| Все пользователи получают 429 при входе | За прокси не передаётся реальный IP — проверьте, что трафик идёт через nginx из поставки |
| Загрузка XML отклоняется | Лимит размера в «Настройки системы» (по умолчанию 20 МБ) |
