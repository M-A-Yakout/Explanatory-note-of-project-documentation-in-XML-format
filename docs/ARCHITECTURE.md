# Архитектура

```
 браузер ──HTTP──> nginx ──/api/*──> API (FastAPI, N workers) ──> PostgreSQL
                    │                      │
                    └── статические файлы   └── lxml: разбор XML и проверка по XSD
                        React-приложения
```

* **Фронтенд** — React + TypeScript + Tailwind, сборка Vite. Роутер с защитой маршрутов по ролям. Одна страница = один файл в `frontend/src/pages/`.
* **Бэкенд** — FastAPI, SQLAlchemy 2, Alembic (миграции), Pydantic (проверка входных данных). Код: `backend/app/` (`routers/` — HTTP, `models/` — таблицы, остальное — предметная логика).
* **База** — PostgreSQL в продакшене; SQLite допустим для разработки (тесты идут на обоих).

## Модель данных

| Таблица | Назначение |
|---|---|
| `organizations`, `users` | Организации (с лимитами) и пользователи; у пользователя ровно одна организация и роль |
| `projects` | Объекты строительства организации |
| `documents` | Пояснительная записка: данные формы (JSON), редакция для защиты от конфликтов, последний результат проверки, статус |
| `document_versions` | Снимки данных документа (история, сравнение, восстановление) |
| `xml_schemas` | Реестр XSD: версия, текст, контрольная сумма, активность, схема по умолчанию |
| `audit_log` | Журнал действий; имя пользователя сохраняется на момент события |
| `invitations`, `notifications`, `settings`, `auth_attempts` | Приглашения, уведомления, настройки системы, счётчики попыток входа |

Данные формы хранятся одним JSON (`object`, `tei`, `composition`, `references`, `additional`) и проверяются Pydantic-моделью `DocumentData` (длины, количество строк). Поиск по кириллице идёт по служебному столбцу `search_text` (нижний регистр считается в Python, потому что `lower()` в SQLite не понимает кириллицу).

## Путь документа

1. **Создание** — из объекта; поля объекта подставляются автоматически, состав — 12 разделов ПП № 87. Создаётся версия 1.
2. **Редактирование** — автосохранение `PUT /documents/{id}/data` с номером редакции; если документ изменён в другом окне, ответ `409 conflict`, чужие правки не затираются.
3. **Проверка** — два уровня:
   * бизнес-правила (`validation.py`): обязательные поля, формат кадастрового номера, ТЭП, «площадь застройки ≤ площади участка», состав, ссылки (в т. ч. устаревшие редакции СП);
   * XSD: из данных строится XML (`xml_builder.py`), проверяется по схеме документа; XPath ошибки сопоставляется с полем формы.
   Дубли (XSD и правило по одному полю) скрываются, но «Соответствует XSD» всегда отражает реальный результат.
4. **Выгрузка** — при скачивании данные **проверяются заново**; сохранённый результат не используется. Ошибки (а при включённой настройке — и предупреждения) блокируют выгрузку.
5. **Правка после проверки** помечает результат устаревшим и снимает статус «Проверен».

## Безопасность

| Угроза | Мера |
|---|---|
| Чужие данные | Каждый запрос ограничен организацией пользователя; чужой объект выглядит как несуществующий (404) |
| Повышение прав | Проверка роли на сервере в каждом маршруте; нельзя менять свою роль и блокировать себя; нельзя оставить организацию без администратора |
| Подбор пароля | Лимит попыток входа по почте (5 / 15 мин) и по адресу (30 неудач / 15 мин); счётчики в БД, общие для всех workers |
| Подмена IP | nginx **перезаписывает** `X-Forwarded-For` реальным адресом клиента |
| Кража сессии | Токен живёт 8 ч; выход, смена и сброс пароля, блокировка немедленно обнуляют все токены пользователя (`token_version`) |
| XXE и «бомбы» в XML | Разбор без сущностей/DTD/сети, лимит размера; `xs:include/import` в XSD запрещены |
| Формулы в CSV | Значения, начинающиеся с `= + - @`, экранируются при выгрузке журнала |
| Старые ссылки приглашений | Ссылка привязана к конкретному приглашению (nonce), отозванная не оживает |
| Небезопасная конфигурация | В `ENVIRONMENT=production` сервис не запустится с ключом по умолчанию, слабым паролем администратора или выключенным лимитом попыток |
| Утечки через кэш | Ответы API: `Cache-Control: no-store`; заголовки безопасности и CSP |

Журнал аудита ведётся для входов (включая неудачные, с IP), действий с пользователями, организациями, схемами, объектами и документами, изменения настроек.
